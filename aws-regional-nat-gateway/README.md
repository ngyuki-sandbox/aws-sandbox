    - オートモードの例
- manual/

## オートモードについて

オートモードでは、AZ 内に EC2 や ECS タスク等のワークロード（ENI）が作成されたことを検知して NAT Gateway がプロビジョニングされる。
新規 AZ へのプロビジョニング完了までの間は、既存の別 AZ にある NAT Gateway を Cross-AZ で経由して外部通信を行う。

基本時間料金は、実際に NAT Gateway がプロビジョニングされている AZ 数（アクティブな AZ 数）に応じて課金される。
そのため、3 AZ に対応した VPC であっても、ワークロードが 1 AZ にしか存在しなければ 1 AZ 分の費用しか発生しない。

ワークロードが 1 AZ にしか存在しない構成であれば、コスト削減目的でマニュアルモード（1 AZ 固定）を選ぶ必要はなく、オートモードのままで問題ない。
ただし、Transit Gateway アタッチメントや Interface 型 VPC エンドポイントなどの ENI もワークロードとして検知されるため、
他 AZ にこれらが配置されていると意図せず複数 AZ へプロビジョニングされ、課金が増やす可能性がある。
そのため、確実に 1 AZ 分のコストに抑えたい（かつ誤プロビジョニングを防ぐ）場合は、マニュアルモードで 1 AZ に固定しておくのが最も確実である。

## 送信元 IP アドレスの固定化

マニュアルモードでは、ユーザー自身が事前に取得した EIP を各 AZ に手動で割り当てるため、送信元 IP アドレスの完全な固定化が可能。
オートモードでは、AZ への自動展開時だけでなく、1 AZ 内の通信量に応じたスケーリングが動的に行われるため、送信元 IP アドレスの固定化は不可能。
